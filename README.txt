handglyph —— 用你自己的手写字生成手写风图片
=================================================

这是什么
--------
给它一张你自己手写的字版照片，它把里面的字逐个切出来建成"你的字形库"；
之后你给一段文字，它就用**你自己的笔画**把这些字重新排到纸面上，输出一张图片。

不是字体渲染，笔画全部来自你本人手写。全程本地计算，不联网、不用 AI 模型、
不产生水印。

----------------
三步跑起来
----------------

1) 装 Python
   需要 Python 3.9 或以上。没装的话去 https://www.python.org/downloads/
   Windows 安装时务必勾选 "Add Python to PATH"。

2) 装依赖
   在解压出来的文件夹里打开命令行，执行：

       pip install pillow numpy scipy

   就这三个是必需的。（可选：想用 OCR 自动从图片提文字，装 pytesseract
   加 tesseract-ocr 程序本体与中文语言包，或装 paddleocr 加 paddlepaddle；
   两条路线二选一即可，不装也完全不影响使用。）

3) 自检一下
   Windows：      handglyph.cmd doctor
   macOS / Linux：./handglyph.sh doctor

   它会逐项检查 Python 版本、依赖、中文字体、背景图、字库状态，
   告诉你缺什么、以及怎么补。全绿就说明环境没问题。

----------------
正式使用
----------------

① 写一张字版，拍照
   在纸上按顺序写下你打算用到的字，拍一张清楚的照片。
   要求：正对纸面拍、光线均匀、对焦准确、发原图不压缩。

② 建字库
   handglyph.cmd build 你的照片.jpg --expect "照片上从左到右的全部字符" -o library

   --expect 必须和照片上的字符顺序完全一致（含标点），程序靠它给每个字命名。
   跑完会生成 library/ 目录和 atlas.png（切分图鉴，用来核对有没有切错）。

③ 检查缺字 / 生成补字单
   handglyph.cmd coverage --lib library -t "你打算写的文字"
   # 缺字会列出来，然后：
   handglyph.cmd form "缺的字" -o 补字单.png --copies 3
   打印补字单，手写填好，再入库合并：

   handglyph.cmd build 补字单照片.jpg --form-sheet --expect "与门输入" \
                --merge --replace -o library

   --copies 3 = 每个字连着写 3 格。**建议就是 3 遍**：
   同一个字多几个实例，排版时轮着用，字迹就不会满篇一副样子。
   抄到第 4、5 遍人会开始敷衍，那几个实例质量反而更差 ——
   写 5 遍的话你不如自己写了。所以定在 3 遍。

   ⚠️ 补字单**必须**带 --form-sheet。补字单上的说明文字、参考字、格线都是
   印刷内容；不加 --form-sheet 会把它们当成你的笔迹吃进字库（实测空白单能
   切出一堆"字形"，全是说明文字碎片，而你真写的字反被丢掉）。
   带 --form-sheet 时程序按格子取字：格位顺序就是字符顺序，格外的一律丢弃。
   入库后跑一次 prune --lib library 淘汰旧差实例。

   ⚠️ **--expect 的长度要正好是 --cols 的整数倍**（默认 --cols 12）。
   form 会按纸面尺寸告诉你一页最多放几个格位，凑满整行再 build。
   长度不是整数倍时，多出来的那几格会被程序编造成 u0164 这样的假字符名
   写进字库 —— 渲不出来也查不到，只能靠删库重来。实测长度 164 配 12 列
   就会多出 4 格，产出 u0164~u0167。

   ⚠️ **补字单上的字要写满、写够重**。程序按"总共读到几个有墨的格子"来
   分配字名，中间漏掉一格，它后面所有字的名字就整体前移一格。
   实测一张 168 格的单子实际写了 156 格、程序只读到 131 格，结果
   25 个字的名字全错位 —— 而你写的字本身一个好都没少。
   入库后**务必看一眼 library/atlas.png**，核对编号和字符对不对得上。

   ✍️ 抄补字单时请**尽量让每个字的笔画粗细一致**（落笔轻重要均匀）。
   不要有的字粗、有的字细，也不要一个字里一半粗一半细。
   原因：补字是分次写的，不同次写的整体轻重会不一样 —— 一次写的字之间是齐的，
   换一次写就可能整体偏粗或偏细。写的时候齐，后面就不用重写。

   ⚠️ 补字单请**现打现用**：旧版程序打印的补字单（v0.2 之前）里参考字是深灰，
   会被当成手写收进库。旧打印件直接作废，用当前版本的 form 重新生成。

   · 如果发现整批字的名字错位了（切分顺序错了），不用重拍：
     先 handglyph.cmd atlas --lib library 看图核对编号，
     再写一个 `序号=字` 的文本文件，执行
        handglyph.cmd atlas --lib library --fix map.txt
     就能就地改名。（--dry 先试算，不动文件）

④ 出图
   先在 examples/ 里挑一个页面描述文件看看格式，然后：

   handglyph.cmd render examples/page3.txt --lib library --paper lined -o out.png

   --paper 可选：white 白纸 / lined 横线 / grid 方格 / redgrid 红格 / cream 米黄
            也可以直接给一张**整幅是纸**的图片路径（见后面"纸面"一节）
   会同时生成 out.audit.txt，是这一页的质检报告（逐字检查合格与否，
   并写明"应渲染几字 / 实际渲染几字"的字数对账）。

   排版说明：行首写 `>` 表示该行缩进两格；太长的行会自动折到下一行
   （想恢复旧的"整行缩小"行为，加 --no-wrap）；每行有轻微的基线起伏，
   不想用就加 --drift 0。

⑤ 自动排版（一页写不满、尾巴上一大片空白时用）

   handglyph.cmd render examples/page3.txt --lib library --paper lined --flow -o out.png

   程序会把整篇内容按"填满一页再进下一页"重新分页：前页写不满就把后面的
   内容提上来填掉空白，内容多了自动分成多页（文件名加 _p1 / _p2…）。

   --flow-slack 240   页尾空白超过这个像素数才算"大片空白"（默认 240）。

   每页的审计报告会写明"正文占多少 / 页尾空多少"，并列出检出的空白段坐标。
   注意：如果整篇内容本身就短（比如只有 5 行），自动排版也无能为力 ——
   没有后续内容可以提上来，报告会如实写"仍偏大"。

----------------
字迹像不像你，靠什么（重要）
----------------

按重要性排序：

  ① 换笔迹 —— 用**你自己的**字库。这是决定性的，别的都是修饰。
  ② 字库容量 —— 补字单抄 3 遍，同一个字多几个实例轮着用。
  ③ 极轻的旋转与形变 —— 默认只有 0.35 度，肉眼基本看不出来。
  ④ 笔画粗细的轻微浓淡 —— 很小很小，只负责"这一次落笔重了一点点"。

  ⛔ 不要指望靠调大 ④ 来"制造差异"。任何你**一眼就能看出这个字更粗**的幅度
     都属于过大。真想让字迹更丰富，去多补几个字的实例（走 ②），
     而不是把粗细拉大。

  想彻底关掉粗细扰动（最保守）：
    handglyph.cmd render ... --stroke 0

----------------
粗细不齐：交给"写的时候一致"，程序不管
----------------
补字是分次写的，不同次写的整体轻重不一样（用 batch 可以比出来，见上一节）。

**v0.7 曾试过用程序改笔画宽度，试了三版都失败，已于本版整块删除。**
不是没写完，是**这件事在数据上做不到**：

  · **细笔画根本不可修**：1~1.5px 的笔画做一次"变细"操作就整条消失。
    实测 1px 竖条要求变细，输出墨量 40 → 40 点，一点没动 —— 它已经只剩 1px，
    退无可退。而"3px 变 2px"这种跳变，观感上不是"更齐"，是"这根笔画没了"。
  · **粗一点的笔画只能整格跳**：加粗一次就是一整圈像素。实测条宽 6/10/16
    加粗时墨量涨幅全是"恰好 1px 宽度"的量，做不到"细一点点"。
  · **连量都量不准**：2px 条与 3px 条量出来**都是 1.0**。所以"看起来没变"
    里头有很大一部分是量尺看不出差别，不是在真比较。

所以现在**粗细一律不动**，只归"墨色浓淡"（`ink_normalize`，改深浅不改几何）。
真要粗细齐，只有两条路，都在写的时候：

  · 照补字单上的要求写，**同一篇里笔画轻重保持一致**；
  · 同一个字多写几遍（`form --copies 3`），选最顺眼的那个。

----------------
字库分批：新补的字比旧库粗/细怎么办
----------------

补字是**分次写**的：一次写的字（同一支笔、同一天、同一种状态）内部轻重一致，
换一次写就可能整体偏粗或偏细。所以每次 --merge 补字都会给字库开一个**新批次**，
程序自己记着"哪些字是哪一次存的"。

   handglyph.cmd batch --lib library

输出形如：

   批间粗细比对（参考字高 40px，基准 0.80）
     批次     日期               字数       中位半径       与基准差  判定
     b1     2026-09-14       52       0.91      13.6%  正常
     b2     2026-09-17        5       0.69     -13.6%  正常

   各批次粗细都在容忍带内（±20%），无需重写。

偏差超过 ±20% 就会判"偏离过大"，并给出要重写的字清单与补字单命令
（想把容差收紧成 ±15%：handglyph.cmd batch --lib library --tol 0.15）。
render 出图时如果批数 ≥2 且超限，也会在末尾自动提示。

⛔ 程序**只提示、不自动改**。自动改是把笔画缩放，会把字弄得不像你写的；
重写才能根治。所以看到提示就按它给的命令出一张补字单，把**旧的那批字和
新的字一起重写一遍**，这两批就归到同一个批次、粗细自然对齐了。

----------------
纸面：内置 5 张，也可以自己导一张
----------------

内置纸面（推荐，最省事）：

    --paper white     白纸
    --paper lined     横线稿纸
    --paper grid      方格纸
    --paper redgrid   红格稿纸
    --paper cream     米黄横线笔记本

也可以**自己导入一张背景图**（直接给图片路径，.png/.jpg/.jpeg 都行）：

    handglyph.cmd render 内容.txt --paper "D:\我的纸.png" -o out.png
    handglyph.cmd render 内容.txt --paper 我拍的纸.png   -o out.png

⛔ **导入的图必须"整幅就是一张纸"，不能带桌面、手掌、书本边缘、笔、水杯等
   纸面之外的东西。**

   字是按"纸面轮廓"摆的：程序先找出画面里的纸面区域，再往这块区域内排版。
   图里混进了纸外之物，那块会被判成非纸面 —— 两种后果：

     · 字只写在一角、大片空白：可用宽度跟着变窄，正文挤在纸面那一块里，
       右边整片空着。**程序不会为这个报警**（轮廓量得出来，它以为正常），
       你只会看到一张怪图。
     · 字跑到纸外、贴到桌子上：若纸面轮廓压根量不出来（画面太暗、纸面被遮
       去大半），排版会退回一个保守宽度硬排，不再知道纸的边界在哪 ——
       于是字一排排写到画面之外，成了"字贴在桌子上"。

   ✅ 该用什么样的图：整幅是纸、平铺正对拍/扫、光线均匀无重阴影、长边 ≥1500px。
      纸上有淡淡的格线/横线没关系（那本来就是纸面的一部分）。

   💡 一句话判据：**把图打开，问自己"如果往这上面写字，每一处都能写吗"。**
      只要有一处不是纸，就把它裁掉、或换一张。

   ⚠ 程序**不会**替你检查这张图是不是纸面 —— 这是刻意的：机器判"这是不是纸"
      必然有误判，误判的代价是"你明明有可用的图却不让用"。所以**得你自己看一眼**。
      （运行 handglyph.cmd doctor 可以再看到这段说明。）

----------------
每轮使用的闭环
----------------
   coverage 报缺字  ->  form 出补字单  ->  手写回传
                                                |
                                   build --form-sheet --merge --replace
                                                |
                                          prune 淘汰差实例  <-+
                                                |
                                      render 出图 + 质检（字数对账）
                                                |
                                    名字错位？atlas --fix 就地改名
                                    粗细不齐？batch 比对批间粗细

----------------
命令一览
----------------
doctor     环境自检（依赖/字体/背景/字库；含"自己导入背景"的说明）
selftest   自检：跑内置回归测试（改代码后先跑它）
build      字版照片 -> 字形库（补字单加 --form-sheet）
atlas      切分图鉴；--fix 按"序号=字"改名字（改名逃生门）
coverage   检查缺字
form       生成补字单（打印出来手写填）；--copies 3 让每字抄 3 遍（推荐）
quality    字库质检：哪些字该重写
shape      形状校验：排查被压扁、墨量过低的字形
batch      字库分批：列各批次、比对批间粗细，超限给重写清单（--tol 调容差）
calibrate  校准质检阈值
prune      淘汰字库里的差实例
clean      对既有字库统一去格线、裁边
extract    从图片提取文本（需 OCR，可选 tesseract / paddle）
render     排版并合成图片；--flow 自动排版（填满一页再进下一页）
           --stroke 0 关掉笔画粗细扰动；--rotate 0.35 旋转上限（度）
           --paper 指定纸面：内置名，或一张"整幅是纸"的图片路径

每个命令都可以加 -h 看详细参数，例如：
   handglyph.cmd build -h

----------------
几个"会拦住你"的设计（别当成 bug）
----------------
· 目标目录已有字库时，直接 build 会被**拒绝**——因为那会整体覆盖旧的字形
  映射，旧 PNG 全变成没人找得到的孤儿文件，而旧版程序**不报任何警告**。
  要加字就加 --merge；只重写照片上这几个字加 --merge --replace；
  确实要推倒重建才用 --rebuild。
· 补字单模式**必须**带 --expect。字符名只能来自它，不给就只能编造 u00xx，
  渲染时对不上号，所以程序直接退出（退出码 2）而不是硬着头皮入库。
· 补字单上**一个字都没读到**时，build 会以**退出码 4**结束（不是 0）。
  跑完了但零产出不该算成功，否则脚本里 `build ... && 下一步` 会把
  "这张单子还空着"当成"建库成功"一路往下走。
· form 与 build --form-sheet 的 --cols 必须同值（默认都是 12），否则格位对不上。
· 有字形的操作（build 并入 / atlas --fix / clean / prune）之后会自动删除
  library/metrics.json。那是全库质检基准，不失效的话新并入的字会被旧基准
  判成离群，prune 会按旧分布删掉好字。
· 字库里某个字形**墨量太低**（比如切分时只框到一小段残笔）时，render 不会
  硬贴上去 —— 贴上去会被放大成一坨实心黑块。程序改用它自己的画点兜底
  （标点类字符），或跳过并在审计报告里说明。用 `shape` 可以查出来是哪个字，
  处置方式是**重写**（拉伸救不回来）。
· 字版/补字单照片上如果**有印刷格线**，而某个字的笔画恰好压在那条线上，
  切分时那条线会被一起抠进字形 —— 成品上就会看到这个字底下多出一根小横线。
  程序会自动切掉这种"与字粘连"的底部横线（判据是它比主体横向**多出一截**，
  真手写的底横不溢出、不会被误伤）。如果你看到还有残留，说明那个字的线与
  主体粘连方式比较特殊，用 `clean --lib library` 再跑一遍统一处理，
  或者干脆重写那个字。

退出码（脚本化调用时按这个判成败）：
  0 成功 / 1 自检失败或发现缺字 / 2 用法或环境错误（含主动拒绝）
  / 3 未预料的运行期错误 / 4 跑完了但零产出
  / 5 跑完了但有内容没落地（render 超页被截断，见下）
  / 130 Ctrl-C 中断

· render 的**超页截断**现在会以**退出码 5**结束，且质检报告首行写明
  「内容被截断」。单页与 --flow 多页两条路径都是如此 —— 脚本里
  `render ... && 下一步` 不会再"少了几行却当成成功"。
· 补字单**装不下**时（列数超纸宽、或字太多排到纸外）form 会直接拒绝，
  并按纸面尺寸告诉你一页最多能放几个格位 —— 不会把格子画到纸外静默少字。

----------------
已知边界（用之前先看一眼）
----------------
· **自由字版的切分仍不稳**：直接拿一张"手写文章"的照片去 build，程序按阅读
  顺序命名，遇到横线纸、打印抬头、墨点就会错名。横线纸照片实测未通过。
  需要精确入库时**一律走补字单路线**（form 出单 → 手写 → build --form-sheet），
  自由字版只适合快速起步。
· **补字单的 --expect 长度要是 --cols 的整数倍**，否则会产出 u0164 这样的假
  字符名（见上文 ③）。
· **补字单格位漏读会让后面的字整体错名**（见上文 ③），入库后一定要看 atlas.png。
· **`quality` 报告里的数字口径不统一**：同一份报告里可能同时出现"需重写 4"
  和"43 个字不合格"这类互相矛盾的数字。差在"按字符算"还是"按字形实例算"。
  **以最后那条"有 N 个字的字形不合格"为准**，它才是 form 该抄的清单。
· **纸面不做检测**：程序不会替你判断导入的图是不是纸面，误判代价太大，
  所以得你自己看一眼（见"纸面"一节）。
· **粗细不齐程序不管**：v0.7 试过用程序改笔画宽度，三版都失败，已整块删除。
  只能靠写的时候保持一致（见"粗细不齐"一节）。
· **一页容量有限**：放不下会以退出码 5 结束并在质检报告首行写明"内容被截断"，
  不会静默少字。多页输出尚未实现，先用 --flow 自动分页。

----------------
关于本包
----------------
包里**不包含**任何人的手写字形库 —— 字形库是个人的笔迹数据，
每个人需要用自己的字版建一份自己的库。

背景纸面（backgrounds/）是程序生成的纯纸纹理，可以放心用。
格式为 JPEG（体积只有 PNG 的约 1/9，肉眼无差别）；你自己放 PNG 进去也能用。

包里还有一份 PACK_INFO.txt，是打包脚本自动写的内容清单（版本、打包时间、
每个文件的字节数）。要核对包里的东西对不对，看它 —— 别信任何手抄的数字。

详细的能力说明、参数默认值、已知边界，见同目录的 能力说明.md。

----------------
从源码运行 / 参与开发
----------------
本目录本身就是一个可运行的源码树，上面所有命令都可以直接用
`python handglyph.py <子命令>` 代替 `handglyph.cmd`。

代码是**单文件** `handglyph.py`（约 6000 行），顶层分类整齐，没有自建包结构。

改完代码请按这个顺序自检：

    handglyph.cmd selftest      # 内置回归测试，70 处断言，全过才继续
    python pack.py              # 打包门禁：静态检查 + 编译检查 + lint + selftest

`pack.py` 会做**静态检查**（例如"模块常量必须先于引用它的函数默认值定义"），
任一环节不过就**不出 zip**。要跳过门禁强制出包用 `--no-gate`，但发版别这么干。

版本号只有一个真源：`pyproject.toml` 的 `version`。包的目录名、zip 名都从它
派生；`pack.py` 会核对它与 `handglyph.py` 里的 `__version__` 是否一致，
不一致只告警不中止（版本号写错是文档问题，不该拦住出包）。

`library/`（字库）、`*.audit.txt`、`atlas.png`、`*.zip` 都在 `.gitignore` 里 ——
字库是**个人的手写笔迹数据**，不要提交进版本库。
